## 第二步：确认你理解了这些核心认知

- 这是**服务端渲染的单文件应用**：HTML/CSS/JS 全内联在 `app.py` 的 Python 字符串里，没有前端框架、没有 ORM、没有飞书 SDK（飞书用标准库 `urllib` 手写）。这是**刻意为之**的简单，不要擅自重构或引依赖。
- **飞书只是登录和通知通道**，不托管本服务。同事在飞书工作台点开的是本服务的公网地址。
- **三级权限 + 角色实时判定**：会话 cookie 只存身份不存角色；角色每请求由 `compute_role()` 实时算（超管白名单 → 数据库 `app_users.is_admin` → claimant）。超管在 `.env` 白名单（根权限），管理员由超管在后台勾选存数据库。
- **分类数据在 `catalog.json`**，不在代码里。
- **金额存"分"**（`amount_cents`）。

## 第三步：本地跑起来（先验证环境，别改代码）

```bash
cp .env.example .env        # 填飞书配置；Secret 找负责人 Lear 拿
pip install -r requirements.txt
uvicorn app:app --port 8000 # 首次启动自动建表
# 打开 http://127.0.0.1:8000/search 自检
```

> 飞书登录需要回调地址公网可达且为 HTTPS，纯本地无法完成登录回调；但**不登录也能访问 `/search`** 看认领搜索和待认领列表。要测完整登录需公网地址，且 `FEISHU_REDIRECT_URI` 与飞书后台一致。
>
> 环境提示：本项目此前的开发机上默认 `python3` 没装 uvicorn，需用 `/usr/bin/python3 -m uvicorn ...`。这是那台机器的环境问题，不是项目要求，你的环境按上面通用命令即可。

## 改代码前必守的红线（详见 DECISIONS.md / DEVELOPMENT_RULES.md）

1. **鉴权只信签名会话**：绝不用表单字段或 URL `?role=` 判断角色；无会话一律 `claimant`。这条曾专门加固，不要倒退。
2. **角色不写回 cookie**，必须实时算（否则改管理员要重登）。
3. **所有进 HTML 的数据走 `esc()`，所有 SQL 参数化**（防 XSS/注入）。
4. **`.env`、`*.db`、`uploads/` 不进 git**；新增敏感配置同步更新 `.env.example`。
5. **数据库改字段用 `ensure_column` 幂等加列**，别写会丢数据的 DDL。
6. **超级管理员只在 `.env` 白名单**，别挪进数据库。
7. 改飞书部署地址 → `.env` + 飞书后台「重定向 URL」+ 飞书**重新发布**，三步同步；飞书加任何权限后也必须重新发布才生效。

## 工作方式

- **当前第一优先级是正式部署**（目前只在临时隧道上跑，不稳）。其余功能增强排在部署之后。具体见 `PROJECT_STATE.md` 和 `DEPLOY.md`。
- 项目**无自动化测试**：改了可观察行为后用 curl/浏览器手动验证再提交。
- 提交规范：中文 commit message，一个完整功能/修复一次提交，结尾保留协作署名行。推送到 `git@github.com:Leariceleto/claim-pool.git`（private，SSH 免密）。
- **每次完成任务、提交前，必须更新 `.ai/PROJECT_STATE.md`**（按它顶部「维护协议」），随代码一起提交。这保证状态文件永远最新、下一个接手者只读它就够。
