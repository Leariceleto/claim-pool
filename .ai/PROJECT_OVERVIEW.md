# 项目概览（PROJECT_OVERVIEW）

## 项目目标

财务到款认领系统。解决的问题：公司收到一笔银行到款后，财务不一定知道这笔钱对应哪个部门/项目。本系统让财务（管理员）导入银行流水，各部门同事通过飞书登录后自助"认领"属于自己的款项，并归类到「部门 / 中心 / 项目」三级分类下，全程留痕可审计。

## 核心功能

- **飞书登录**：企业自建应用，飞书 OAuth2 网页授权登录，同事用飞书账号即可进入。
- **认领搜索**：普通用户按客户名/金额/备注搜索款项并认领（搜索可见金额）。
- **待认领列表**：公开的待认领款项列表，支持按到款日期筛选；**不显示金额**（保护财务信息）。
- **三级分类认领**：认领时按「部门 → 中心/小组 → 项目」三级联动单选（数据见 `catalog.json`，当前 12 个部门）。
- **个人中心**：展示当前用户身份卡 + 自己的认领记录；首次登录可设置本人部门。
- **管理后台**：导入流水、确认入池、编辑流水、处理状态、成员部门管理、管理员管理、全量操作日志。
- **驳回退回**：管理员驳回某人的认领 → 飞书私信通知本人 → 单子退回待认领池重新开放。
- **三级权限**：超级管理员 / 管理员 / 普通用户（详见 ARCHITECTURE.md）。
- **操作审计**：搜索、认领、导入、驳回、授权等关键动作全部写入 `audit_logs`。

## 技术栈

- **语言/运行时**：Python 3.12（见 `.python-version`）
- **Web 框架**：FastAPI 0.115.6 + Uvicorn 0.34.0
- **依赖**：仅 `fastapi` / `uvicorn[standard]` / `python-multipart`（见 `requirements.txt`）。
  **飞书 OAuth 登录、发消息全部用 Python 标准库 `urllib` 手写实现，没有引入飞书 SDK 或任何 HTTP 客户端库。**
- **数据库**：SQLite（单文件 `claim_pool.db`），无 ORM，直接用 `sqlite3` 模块写 SQL。
- **前端**：无前端框架。HTML 直接用 Python f-string 内联在 `app.py` 里，原生 `<form>` 提交 + 少量内联 JS（三级联动下拉）。CSS 也内联在 `app.py` 的 `BASE_CSS` 常量。
- **整个应用是单文件 `app.py`（约 1980 行）。**

## 部署方式

- **当前（开发/试用）**：跑在开发者本机，前面用 cloudflared 临时隧道（`*.trycloudflare.com`）暴露公网。**临时方案，地址会变、不稳定，仅供试用。**
- **生产（计划中，未落地）**：两条路径，详见根目录 `DEPLOY.md`：
  - A. 腾讯云轻量服务器（已有一台），需域名 + SSL + 可能备案。
  - B. Zeabur 等托管平台（已备 `Procfile` + `.python-version`，挂持久卷给 SQLite/上传目录）。
- **持久化**：数据库和上传目录路径由环境变量 `CLAIM_POOL_DB` / `CLAIM_UPLOAD_DIR` 指定，部署时指向持久磁盘。
- **代码仓库**：GitHub（private）`https://github.com/Leariceleto/claim-pool`
