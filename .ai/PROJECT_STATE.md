## 已知问题

- 飞书请求 UUID 的服务端去重窗口为 1 小时；发送成功但落库前崩溃、超过窗口才恢复仍可能重复，不能承诺跨系统严格恰好一次。租约 5 分钟，失败指数退避（60 秒起，上限 1 小时），发送结果按接收人持久化。
- 原有历史异常净额不自动修改。启动迁移发现异常 pending 认领会跳过并记录 payment_id；相关操作/导出会拒绝不合法净额，需财务核对后明确修正。

- 临时隧道（trycloudflare）地址会变、跨天失效，仅开发期可用（正式部署后消失）。
- 飞书部门未自动从组织架构读取，靠用户首次自选 + 管理员后台调整（原因见 `DECISIONS.md`，是有意取舍）。
- 本地 `claim_pool.db` 不随 git 同步，可能含本机验证数据；生产数据库须独立备份，不得用本地库覆盖或清空。
- 驳回通知依赖接收人在飞书应用可见范围内，范围外发送失败（容错不报错，但人收不到）。
- 入池群通知依赖 `FEISHU_NOTIFY_CHAT_ID`、机器人入群、`im:message:send_as_bot` 权限和应用重新发布；未配置或发送失败不阻断确认入池。
- 无银行流水号的表格行不自动去重；若整份文件重复上传，会再次入池，导入前需确认文件未处理过。
- 单文件 `app.py`（HTML 内联），82 项回归测试；本轮覆盖并发、权限、金额、状态、通知队列及交互响应，真实飞书及生产环境仍需部署验收。
- SQLite 单文件。数据库不在 git，需单独备份；是否迁移由实际并发和查询指标决定，不按数据条数直接认定需要重写。
